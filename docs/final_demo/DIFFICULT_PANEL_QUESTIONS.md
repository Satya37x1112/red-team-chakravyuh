# CYBER CHAKRAVYUH — Difficult Panel Questions (20)

1. **Why trust an AI-generated plan?** We don't — the plan is *untrusted input*. It's a Pydantic `ExecutionPlan` with no field that can set caps or authorize; the deterministic Safety Gateway (`gateway.evaluate()`) re-checks everything. *Evidence:* `plan_schema.py`, `gateway.py`. *Follow-up:* "What if the schema itself is wrong?" → `extra="forbid"`, strict validators, tests.
2. **LLM produces a malicious/malformed plan?** Malformed → Pydantic `ValidationError` before the gateway. Malicious-but-valid → gateway rejects unauthorized target/module/op/caps. *Evidence:* `test_plan_schema.py`, `test_gateway.py`. *Follow-up:* "Prompt injection?" → the AI can only pick from allowlisted modules/targets; execution is backend-gated.
3. **Can the AI bypass the Safety Gateway?** No — AI output never reaches an adapter except via `evaluate()`→Registry→Dispatcher; the AI has no execution handle. *Follow-up:* "Legacy routes?" → see Q8.
4. **What prevents an unauthorized target being selected?** `authorize_recon_target()` / `policy.is_target_authorized()` — RFC1918-lab or tailnet-peer only; public/loopback/hotspot refused; fail-closed. *Evidence:* `collector.py`, `test_discovery_security.py`. *Follow-up:* "Manual entry?" → same function, same checks.
5. **How does dynamic hotspot protection work?** `prohibited_networks()` = configured CIDRs **+ the live default-route subnet** (`_default_route_subnet()`), so the Wi-Fi Kali is on is auto-blocked even on a new network. *Evidence:* verified live rejecting `10.189.4.0/24`. *Follow-up:* "If `ip route` fails?" → fail-closed + configured fallback.
6. **Two discovery scans start simultaneously?** Atomic count+reserve under one lock in `start_scan` (TOCTOU-fixed). *Evidence:* `test_high02_concurrent_requests_do_not_overshoot` (8 threads, limit 2 → exactly 2). *Follow-up:* "Slot release?" → on terminal state.
7. **How is the kill switch enforced?** `kill_switch.is_engaged()` at the top of `evaluate()` and in every network route (423); reset requires `SAFETY_ADMIN_TOKEN` (no unauthenticated reset). *Evidence:* `killswitch.py`, `test_killswitch.py`. *Follow-up:* "Mid-run process?" → process-group termination for adapter subprocesses.
8. **Which routes bypass the unified pipeline?** `/api/telemetry/probe`, `/api/attacks/soc-activity`, `/api/assessment/run`, `/api/auth/live-validate`, `/api/transfer/send` — they use central authz+kill-switch+audit but not Registry/ExecutionPlan. *We state this openly.* *Follow-up:* "Risk?" → still authorized+audited+kill-switched; gap is unified lifecycle tracking.
9. **Synthetic vs real telemetry?** Real = measured probe/Locust output; simulation is explicitly labeled ("SIMULATION — NO NETWORK TRAFFIC"); unavailable (Windows internals) reported as unavailable. *Follow-up:* "Could a demo fake it?" → results come from adapters, not the UI.
10. **Does it perform a real DDoS?** No — Locust is **capped** (≤50 users/≤120 s) bounded HTTP load; the "ddos" signature is a **bounded connection burst**, not a flood. No SYN/UDP/amplification. *Follow-up:* "Prove the cap." → gateway clamp + `test_availability_module.py`.
11. **Is Hydra doing real auth attempts?** Not in this task — **MOCK VERIFIED** only. Live mode exists but is capped (≤3 attempts/account, non-admin, lockout-aware) and was not run. *Follow-up:* "What stops spraying?" → attempt cap + allowlist.
12. **Evidence Wazuh detects an operation?** **None in-code** — CHAKRAVYUH has no Wazuh/SIEM forwarding. Detection needs a Wazuh agent + rules on the target. We do not claim otherwise. *Follow-up:* "So how would you prove detection?" → agent installed + 4625 rule + online target.
13. **OpenRouter unavailable?** Centralized client returns `(None, None, errors)`; planner uses deterministic fallback labeled FALLBACK; UI shows AI unavailable; no fabrication. *Evidence:* `_llm.py`, `test_live_llm.py`.
14. **Why NetExec not live-verified?** Target offline → honest **IMPLEMENTED—NOT LIVE VERIFIED**. Operations are read-only (5 fixed), creds via stdin. *Follow-up:* "Arbitrary commands?" → impossible; only fixed operation identifiers.
15. **How is file integrity established?** SHA-256 computed before send and after receipt; mismatch = failure; filename/path sanitized; 10 MB cap; received files not executed. *Evidence:* `transfer.py`, `test_transfer_module.py`.
16. **Current architectural weaknesses?** Non-unified routes (Q8); in-memory registry (per-process); no Wazuh connector; env mismatch; single AI provider. All documented.
17. **Credential exposure risk?** Secrets in gitignored `.env` (600), masked in audit/API/exceptions, NetExec creds via stdin (brief argv exposure is the one documented caveat). *Follow-up:* "Process list?" → stdin/secret-file used where possible.
18. **In-memory registry survives restart?** No — it's per-process; audit (SQLite) persists. A limitation for long-running lifecycle tracking.
19. **What if the operator is malicious?** The platform bounds *capabilities* (allowlist, caps, read-only ops, no shell), and audits everything — but it assumes an authorized operator; it is a lab tool, not a zero-trust product.
20. **Is it production-ready?** No — **lab demonstration** readiness. Verdict READY WITH LIMITATIONS; two external dependencies blocked.
