Added Hydra as the **BruteForce module's real credential-test driver** — exactly
like Locust is the real driver for the DDoS module. The module's `execute()`
stays a simulation; the real path lives behind a **fail-closed integration

**Safety posture (project boundary preserved):**
- Fail-closed gate: `HYDRA_ENABLED=true` + authorized target + user-list + pass-list — all four required
- Hard caps: attempts (500), parallel tasks (4), duration (120s) — a request can lower them, never raise them
- Fixed scope: only that one list-pair, that one target+service — no arbitrary host/creds from a request
- No shell, hard timeout; the **cracked password is never returned to the UI** — it only reports "login X has weak creds"
- Missing binary/config → the adapter honestly reports "unavailable"/"disarmed", never a crash

## 4. Live SMB test (on this device, authorized self-test)

- Target: this Windows host's SMB (`172.26.240.1:445`) — had to add a temporary
  scoped firewall rule for WSL→host (`TEMP-WSL-SMB-hydra`, WSL subnet `/20`)
- **Result (honest):** the whole pipeline ran correctly — detect → armed →
  reachable → run → parse → save artifact → surface error. But **hydra 9.5's SMB
  module can't negotiate with modern Windows 11 SMB (SMBv3 + signing)** →
  `[ERROR] invalid reply from target`, 0 valid pairs. No fabricated results.
- This is a real-world finding: SMB brute-force is flaky on Win11; an SSH-based
  throwaway target is the reliable way to demonstrate a successful crack.

> **Cleanup reminder:** remove the firewall rule when testing is done —
> `Remove-NetFirewallRule -DisplayName "TEMP-WSL-SMB-hydra"`

## 5. Bug fixes

1. **Frontend wouldn't run on Windows** — in `frontend/src/pages/`, `Report.tsx`
   (a component) and `report.ts` (helpers) differed only by **case**; on a
   case-insensitive filesystem (Windows/macOS) that caused an import collision →
   Vite dep-scan crash. Fix: renamed `report.ts` → `reportHtml.ts` and updated the
   importer. (It was hidden on Linux.)
2. **DDoS/Locust "not working"** — the target `http://localhost:8080` had nothing
   listening (the Docker frontend wasn't started). Pointed it at
   `http://localhost:5173` (the live Vite server) → verified 8 requests, 0
   failures. (`.env` change — gitignored.)
3. **Hydra wrapper was corrupted** — when first created via a WSL heredoc, Git Bash
   had stripped the `$@`/`$a` shell variables to empty → hydra received an empty
   arg → syntax help. Rewrote it correctly with the Write tool; args now pass
   through fine. Also added `.gitattributes` so `.sh` files stay LF.
